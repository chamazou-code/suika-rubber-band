# v1設計と作業記録

## 参照動画の観察

実装前に46.35秒の添付動画を確認し、18.7〜20.26秒を65ms刻みで観察した。

- 19.55秒付近まで中央の輪ゴム束がスイカを圧迫。
- 19.61〜19.68秒で上部が一気に上昇。下部の赤い断面はテーブル上に残る。
- 19.74秒には上部の断面が人物の顔の位置へ到達。果肉・汁も上へ舞う。
- 19.8〜20.2秒では人物が後ろへのけぞり、上部が落下していく。

ゲームではこの方向性を固定。左右の二分割にせず、上部が240msで顔へ到達する。140msのヒットストップ後にのけぞりと落下を再開。下部は作業台に残す。

## 実装順序

1. 純粋なルールと隠し耐久、判定・連打ロック。
2. 少ないDOMと、人物・スイカ・メーターを描くCanvas。
3. くびれ、輪ゴム束、縦方向の射出、顔への果肉衝突。
4. Web Audioのオリジナル合成音。
5. 320px・縦長・横画面、キーボード、reduced-motion。
6. ルールテスト、ブラウザテスト、実時間の繰り返しプレイ。
7. Production build、GitHub、Cloudflare PagesのGit連携。

## ゲームフィール

SAFE幅は `max(0.065, 0.28 - bands * 0.0043)`。
針の速さは1秒当たりメーター幅の `min(1.35, 0.64 + bands * 0.014)`。
本数30でSAFE約15%、50で6.5%。SAFE中央34%がPERFECT。

中央から逸れた操作で蓄積する隠しダメージが最終本数を減らす。耐久は表示せず、外観の緊張度は本数だけから計算し、実際の残り耐久を漏らさない。

## ライフサイクル

- requestAnimationFrameは常に1本。背景タブでは停止し、復帰時の時間差を捨てる。
- 状態はready → playing → cracking → bursting → result。再挑戦ですべてを初期化。
- ゲーム進行にsetTimeout/setIntervalを使わない。
- 波形・ノイズは1個のAudioContextで生成。各音の終了時にノードを切断。ノイズバッファは再利用。
- ResizeObserver、イベント、アニメーションを破棄。BFCache復帰では再利用。
- 派手な飛沫は最大120個、DPRは最大2。粒子の軌道は時刻から計算。
- イベント時だけ本数・判定・結果のDOMを更新。毎フレームはCanvasのみ。

## v1.1 UI調整

- アイボリー、セージ、濃い緑で統一し、紙の細かな質感・木のテーブル・ボタンの薄い段差を追加。
- Outfitをローカル配信。見出し、本数、メーターの英数字を揃え、日本語にはシステムフォントを使用。
- 本数と判定の位置はCanvasと同じ座標から算出し、端末サイズに追従。
- 1本を巻いた直後に、本数の小さなポップ、判定バッジ、ボタンの押し込み、輪ゴムの接近を表示。Web Animationsは同じ要素の前回分を取り消し、再挑戦と破棄時にすべて解除。
- 結果は本数を主役にしたチケット形式。果肉まみれの顔は見せたまま、操作盤を再挑戦の案内へ切り替える。
- reduced-motionでは追加のポップや押し込みも停止。ルール、難易度、破裂の方向とタイミングはv1.0と同じ。
